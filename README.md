# 墨读 · 公版书库

一个自托管的公版书阅读站：366 本典籍（300 本中文古籍 + 66 本西方经典，共 1.65 万节、约 3900 万字中文 / 1435 万词英文），支持英译中实时翻译、文言文白话今译、目录与书名全中文化，也可以把自己手里的纯文本导入书库。

## 隐私与数据

- **所有内容都在服务器**：正文、章节、译文、目录译名全部来自 `data/` 与服务端接口，前端不下载整本书。
- **不在浏览器留任何东西**：不写 localStorage、不写 sessionStorage、不写 cookie、不生成设备号、不加载第三方统计脚本。字号、主题、语言选择、阅读位置都只存在当前页面的内存里，刷新即归零。
- **不收集用户信息**：没有账号、没有登录、没有埋点，服务端不记录「谁上传了什么」。导入的书直接进入公共书库，所有人都能看到——请勿导入不愿公开的内容。
- **译文落在服务器**：一章译完即写回 `data/books/*.json.gz`，重启、扩容、换设备都不用重译。

## 一、快速启动

```bash
# Python 3.11+
pip install -r requirements.txt
PORT=8000 ./start.sh
# 或
python -m uvicorn app:app --host 0.0.0.0 --port 8000
```

Docker：

```bash
docker build -t modu-reader .
docker run -p 8000:8000 modu-reader
```

无需数据库、无需构建步骤、无 Node 依赖。

## 二、环境变量

| 变量 | 作用 |
|---|---|
| `PORT` | 监听端口，默认 8000 |
| `TRANSLATE_BASE_URL` / `OPENAI_BASE_URL` | 翻译接口地址，OpenAI Chat Completions 兼容 |
| `TRANSLATE_API_KEY` / `OPENAI_API_KEY` | 接口密钥 |
| `TRANSLATE_MODEL` | 模型名，留空自动向 `/models` 探测 |
| `ADMIN_TOKEN` | 删除导入书籍所需口令；不设则关闭删除功能 |
| `HIDDEN_KEY` | 隐藏书柜暗号，默认 `zxcv`；只在搜索框里输入，界面无入口 |

翻译配置也可以写成 `.secrets/translate.json`：

```json
{"base_url": "https://your-endpoint/v1", "api_key": "sk-xxxx", "model": "your-model-name"}
```

> 发布包里**没有附带任何密钥**。密钥只在服务端读取，不会出现在前端代码或接口响应中。

## 三、导入与更新

书架工具栏点「＋ 导入书籍」，可以拖入 `.txt` / `.md`，也可以直接粘贴正文。

- 编码：UTF-8 优先，出现乱码自动按 GB18030/GBK 重读。
- 切章：识别「第一章 / 第 1 回 / 卷一 / 序 / 楔子 / Chapter N / Book N / Part N」等行首标题；只有标题没有正文的目录页会被丢弃。
- 没有可识别标题时按 6000 字左右切节，优先在句号处断开。
- 超长单章（2 万字以上）会再切一次，避免一次返回几兆正文。
- 自动判定语种：中文书走文言今译通道，英文书走英译中通道，和内置书完全一样。
- 单本上限 600 万字，导入总量上限 2000 本。

### 关于正文框

正文框高度固定 150px，**不随粘贴或上传的内容变长**，超出部分在框内滚动，弹窗高度保持不变。

选择文件后，框内只显示前 600 字作预览并置为只读，完整正文已读入内存；导入时以文件内容为准，不会因为框里只有预览而被截断。点文件名右侧的「清除」可放弃文件，改回手动粘贴。

### 同名书怎么处理

以前每次导入都会生成新 id，所以同一本书导入两次就会变成两本——这也是「为什么不能更新旧书」的原因：没有覆盖入口，只有新增。

现在导入时会先做同名检测（书名归一后比较，作者只作加分项），命中则弹窗让你二选一：

- **确定：覆盖更新** —— 沿用旧书 id，替换正文与章节，按「章标题 + 段落数完全一致」逐章保留旧译文，对不上的章节丢弃重译。章数一变，该书在 `cn_titles.json` 里的目录译名会整条摘掉（避免错位），`data/cn_cache/<书号>/` 也会清空（缓存按章号存，更新后可能张冠李戴）。
- **取消：另存为新书** —— 旧书不动，新内容作为独立一本入库。

覆盖前会把原书备份到 `data/books/.bak/<书号>-<时间戳>.json.gz`，每本只留最近三份，改坏了可以直接拷回去。内置书同样可以被覆盖（比如用全本替换残本），备份机制就是为此准备的。

删除：打开导入的书，标题栏右侧有「删」，输入 `ADMIN_TOKEN` 即可删除。内置书不可删。

## 四、阅读操作

阅读器打开后（且导入弹窗关闭、焦点不在输入框里）可用以下操作：

| 操作 | 效果 |
|---|---|
| `W` / `↑` | 向上滚动约一屏 |
| `S` / `↓` | 向下滚动约一屏 |
| `A` / `←` | 上一回 |
| `D` / `→` | 下一回 |
| 触屏左右轻扫 | 上一回 / 下一回（横向位移需大于 70px 且明显大于纵向，竖滑与选字不会误触） |
| `Esc` | 退出阅读器 |
| `Ctrl/⌘ + K` | 聚焦书架搜索框 |

在输入框、文本域、下拉框里打字不会触发快捷键；`W/S` 只在正文区域内滚动，不影响页面其它部分。

## 五、隐藏书柜

有些书不想摆在公开书架上，可以放进隐藏书柜。

- **入口是藏起来的**：界面上没有任何按钮。在搜索框输入暗号 `zxcv` 后按回车，才切换到隐藏书柜；再输一次暗号（或点提示条上的「退出」）回到公开书架。
- **暗号在服务端校验**：前端源码里不出现 `zxcv`，输入什么就原样送到 `/api/hidden/check` 比对，可用 `HIDDEN_KEY` 环境变量更换。
- **公开书架彻底看不到**：`/api/library` 只返回 `hidden=false` 的书，统计同样分开算。
- **在隐藏书柜里导入**，弹窗会多出「放入隐藏书柜」并默认勾选；在公开书架导入则没有这个选项。

> 注意：这是**入口隐藏，不是权限控制**。知道暗号的人都能进；知道书号 `id` 的人也能直接打开 `/api/book/{id}`。适合「不想被随手翻到」，不适合存放真正敏感的内容。

## 六、目录结构

```
app.py                 FastAPI 入口：书架 / 章节 / 翻译 SSE / 导入 / 删除
trans.py               翻译内核：配置、分块、并发、落盘、双语提示词
importer.py            导入内核：编码归一、切章、语种判定、原子入库
requirements.txt
start.sh               启动脚本（读取 $PORT）
Dockerfile
static/
  index.html           单页外壳（不含任何书内容）
  app.js               前端逻辑（无本地存储）
  style.css
data/
  library.json         书架索引：含分类/语种/字数/译文标志/文言系数/来源
  books/*.json.gz      每本书的完整内容：chapters[{title,text,cn,cn_title}]
  books/.bak/          覆盖更新前的原书备份（每本保留最近三份）
  cn_titles.json       66 本英文书的目录中文标题（4134 行）
  cn_cache/<书号>/      实时译文缓存（断点续译用，逐章 JSON）
tools/                 离线运维脚本（重建索引、批量译标题、同步译文等）
```

`data/` 是全部内容所在，也是最需要备份的目录。书籍文件用 gzip 存储，单本 1 KB–3 MB。

## 七、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/library?q=&cat=&sort=` | 书架列表（搜索、分类、排序） |
| GET | `/api/stats` | 总量、分类统计、导入数量 |
| GET | `/api/book/{id}` | 书籍元信息 + 目录（含中文标题） |
| GET | `/api/book/{id}/ch/{idx}` | 单章正文（原文 + 已译中文） |
| POST | `/api/book/{id}/ch/{idx}/translate` | 实时翻译，SSE 流：`meta/part/prog/done/err` |
| GET | `/api/translate/status` | 翻译服务状态、缓存统计、落盘健康度 |
| POST | `/api/import` | 导入书籍，body：`{title, author, cat, text, hidden?, replace?, allow_duplicate?}` |
| GET | `/api/hidden/check?key=` | 校验隐藏书柜暗号，只返回 `{ok}` |
| GET | `/api/library?hidden=1` | 隐藏书柜列表，需 `X-Hidden-Key` 头 |
| GET | `/api/stats?hidden=1` | 隐藏书柜统计，需 `X-Hidden-Key` 头 |
| DELETE | `/api/book/{id}` | 删除导入的书，需 `X-Admin-Token` |
| GET | `/api/cn/manifest` | 已落盘译文清单 |
| GET | `/api/cn/export?book=` | 导出译文（备份/迁移） |

## 八、翻译是怎么工作的

1. 章节按 ~2600 字符 / 每块不超过 14 段切块，3 块并发请求。
2. 提示词强制模型只返回 `{"title":"…","paras":["…"]}`，段数必须与原文严格一致，不一致自动重试。
3. 英译中与文言今译是两套提示词：后者不跨语言，重点在「不加戏、不漏句、不文白夹杂」，人名官名年号照录、干支不改公历、诗句不强行散文化。
4. 每块完成即写 `data/cn_cache/<书>/<章>.json`；整章完成后由后台线程合并进 `data/books/<书>.json.gz`（原子替换），并置 `has_cn`。
5. 已译章节再次打开直接读文件，实测 0.17–0.48 秒。

首次阅读未译章节仍需等待（英文 4–30 秒/章，文言 10–30 秒/章），这是按需翻译的固有成本；需要零等待可用 `tools/` 里的脚本整本预译。

## 九、运维脚本

| 脚本 | 用途 |

## 十一、已知限制

- 未译章节首次打开需要等待，不是 bug。
- 导入的书默认公共可见，没有权限隔离；隐藏书柜只是入口隐藏，不是权限。
- 覆盖更新保留译文的前提是「章标题相同 + 段落数相同」，译文仍在旧段落上时会被丢弃，需重译。
- 少数多卷本（如《罗马帝国衰亡史》）保留了原书目录页，章节顺序看起来偏长，属原书结构。
- 《封神演义》《镜花缘》等半文半白作品被阈值排除在今译之外，可在 `app.py::_can_modern` 加白名单。
- 阅读进度不做持久化：不写浏览器存储，也就不存在跨会话续读。这是「不采集任何信息」的取舍。
